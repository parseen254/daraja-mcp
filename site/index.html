Why another M-Pesa server

Several already exist. Most wrap one endpoint and stop. Three things make Daraja genuinely awkward, and they are the three this handles.

The result is not in the response

You initiate a payment, get an acknowledgement, and the real outcome arrives on a webhook a minute later. The *_and_wait tools block on the callback and return the receipt number, so a model learns whether money actually moved.

Callbacks are unsigned

Safaricom does not sign callback bodies. An open callback endpoint lets anyone mark an unpaid order as paid. Inbound callbacks are checked against Safaricom's published ranges, with an optional unguessable path secret. Verification cannot be switched off in production.

You cannot test it without an account

Daraja needs credentials and a public HTTPS callback URL before the first request works. The bundled simulator speaks the real endpoints, returns the real shapes, and pushes callbacks the way Safaricom does.

What a payment looks like

One tool call, start to settled, with no Safaricom account.

{
  "status": "success",

Failure paths are deterministic

Scenarios key off the amount, so you can exercise every branch locally instead of finding them in production.

AmountOutcome
100Success, with a receipt
1Insufficient funds
1032Cancelled by user
1037Timeout, customer unreachable
2001Wrong PIN
9999Upstream 500, to exercise retries

Failed payments carry no CallbackMetadata at all, exactly as on real Daraja. Code that reaches for the receipt number without checking breaks here rather than at 2am.

Tools

Twenty-five, across the whole Daraja 3.0 surface.

Payments

stk_pushSend a payment prompt. Acknowledgement only.
stk_push_and_waitSend a prompt and wait for the customer. Returns the receipt.
stk_queryCheck the status of a previous prompt.
ratiba_createCreate a standing order for recurring collection.
ratiba_create_and_waitCreate one and wait for approval.
generate_qrGenerate a dynamic QR code.

Disbursement and treasury

b2c_paymentPay a customer: refunds, withdrawals, salaries.
b2c_payment_and_waitSame, returning the settled result.
b2b_paymentPay a PayBill, a till, or top up a B2C account.
tax_remittanceRemit tax to KRA against a PRN.
business_to_pochiPay a Pochi la Biashara number.
account_balanceQuery your business account balance.
transaction_statusLook up any past transaction.
reversalReverse a transaction paid into your shortcode.

Identity and fraud (new in Daraja 3.0)

check_sim_swapWhen was this number last SIM-swapped?
check_age_on_networkWhen was this number first registered?
validate_identityIs this number registered to this national ID?
query_org_infoWhat business owns this shortcode, at what tariff?

Checking for a recent SIM swap before disbursing to an unfamiliar number is a cheap control against SIM-swap fraud. query_org_info catches a fat-fingered shortcode before the money leaves.

C2B and diagnostics

c2b_register_urlsRegister validation and confirmation URLs.
c2b_simulateSimulate a customer payment. Sandbox only.
pull_registerRegister for the Pull Transactions API.
pull_transactionsFetch C2B transactions for a window.
list_callbacksRecent callbacks, newest first.
get_callbackFull payload for a correlation id.
server_healthMode, credentials, receiver status.

Daraja's own inconsistencies

Reproduced deliberately rather than tidied up, because Daraja rejects the corrected forms. Worth knowing whether or not you use this server.

  • B2C sends InitiatorName; B2B and the treasury APIs send Initiator.
  • RecieverIdentifierType is misspelled in the specification.
  • B2C expects Occassion; transaction status expects Occasion.
  • Ratiba's sample says StandingOrderNameName while its parameter table says StandingOrderName. Both are sent.
  • Ratiba's sync response uses ResponseHeader and code 200; its callback uses responseHeader and code 0. Different casing, different code space, same product.
  • STK ResultCode is numeric; most other products send it as a string.
  • Timestamps must be East Africa Time. UTC backdates the request three hours and Daraja rejects it as expired. The most common STK bug there is.
